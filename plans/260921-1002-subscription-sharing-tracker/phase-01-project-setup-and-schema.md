# Phase 1: Project setup and schema

## Overview

Scaffold Next.js app cloned from sono conventions, D1 + Drizzle schema, migrations, query helpers, money utils.

## Requirements

- Functional: all tables from brainstorm data model exist with FK + indexes.
- Non-functional: same tooling as sono (pnpm, eslint, tsconfig, wrangler.toml, next-on-pages).

## Architecture

Tables (`lib/db-schema.ts`, Drizzle sqlite):
- `payment_accounts(id, currency, label, details)`
- `subscriptions(id, name, currency, price_per_month, payment_account_id, remind_days_before NULL)`
- `members(id, name, email UNIQUE, user_id NULL, archived DEFAULT 0)`
- `memberships(id, member_id, subscription_id, monthly_share, is_family, paid_through, archived DEFAULT 0, UNIQUE(member_id, subscription_id))`
<!-- Updated: Validation Session 1 - archived flags instead of deleting rows with history -->
- Env names follow sono, except `APP_URL` (sono: `NEXT_PUBLIC_APP_URL`, which Next inlines at build time): `APP_URL`, `RESEND_FROM_EMAIL`, `RESEND_API_KEY`, `BETTER_AUTH_SECRET`, `ADMIN_EMAILS`.
- `payments(id, membership_id, months_covered, amount, status, note, reject_reason, created_at, decided_at)`
- `reminder_log(id, membership_id, due_date, kind, sent_at, UNIQUE(membership_id, due_date, kind))`
- `fx_rates(date, base, quote, rate, PK(date, base, quote))`
- better-auth tables added in phase 2.

Money: integer minor units per currency (JPY 0 decimals, VND 0 decimals) => store integers; helper `formatMoney(amount, currency)`.
Dates: store `paid_through` as `YYYY-MM-DD` text; helper `todayJst()`, `addMonths(date, n)` (clamp end-of-month).

## Implementation Notes (as built)

- Migration is generated by `drizzle-kit generate --name init` into `d1/migrations/0000_init.sql` (wrangler `migrations_dir`), not hand-written, so schema and SQL cannot drift. Regenerate with `pnpm db:generate` after schema changes.
- `next.config.mjs` instead of `.ts`: `setupDevPlatform()` needs top-level await, which the CJS-transpiled `.ts` config breaks.
- `reminder_log` uniqueness is a **partial** unique index `WHERE kind != 'manual'`, so admin can re-send manual reminders while cron milestones stay once-only.
- `lib/env.ts` deliberately not created yet (no code reads env until phase 2; `cloudflare-env.d.ts` types the bindings).
- `wrangler.toml` `database_id` is a placeholder; run `wrangler d1 create subscription-tracker-db` before deploy (phase 7).
- `pnpm-workspace.yaml` `allowBuilds` enables esbuild/workerd/sharp/swc/parcel-watcher/unrs-resolver install scripts.
- `vitest.config.ts` sets `css.postcss` inline to avoid loading Next's string-plugin PostCSS config.

## Risk Assessment

- SQLite has no enum: enforce status/kind via zod + CHECK constraint.
- Month-end drift in `addMonths`: cover with tests.
